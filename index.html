2

Lanzar el Servidor Bridge (pt_listener.py)

¡Paso Crítico!
⚠️

ORDEN OBLIGATORIO: Antes de conectar o ejecutar el script en Cisco Packet Tracer, debe estar iniciado y corriendo este servidor en tu terminal para que el puerto de enlace 4242 esté disponible para recibir la conexión.

Abre una terminal y ejecuta el script listener:

cd pt-mcp-server\src\bridge && python pt_listener.py

O directamente desde la ruta: pt-mcp-server\src\bridge>python pt_listener.py. Verás el mensaje: "Packet Tracer Listener started on 0.0.0.0:4242". Deja esa terminal abierta en segundo plano.

3

Conectar la Extensión en Cisco Packet Tracer

  1. Abre tu software Cisco Packet Tracer.
  2. En el menú superior haz clic en: Extensions ➡️ Scripting ➡️ Configure PT Script Modules... (o Script Manager).
  3. Haz clic en el botón Add... y selecciona el archivo MCP-Control-Center.pts del proyecto (o pt_listener.py).
  4. Presiona Yes si te pide confirmación.
  5. Se abrirá la ventana MCP Control Center conectándose en vivo al servidor listener del Paso 2. ¡Déjala abierta o minimízala!

Scripts de Instalación (.bat / .sh) vs. Modo Manual Paso a Paso

Inspecciona el código fuente exacto línea por línea o realiza la instalación de forma 100% manual.

💡
¿Por qué usar estos documentos en lugar de hacerlo a mano?

Los scripts install.bat e install.sh existen precisamente para automatizar todo el despliegue en un solo paso y evitar que tengas que escribir comandos línea por línea en tu terminal. Al ejecutarlos, ellos realizan de manera secuencial la actualización de pip, la descarga de requirements.txt y la ejecución de setup_project.py sin intervención humana. Solo debes usar el Modo Manual si deseas personalizar el entorno, auditar el código o si estás en una terminal restringida.

Preguntas Frecuentes y Diagnóstico

                
Respuestas técnicas sobre el funcionamiento del puente y la extensión.

            


            

                

                    
¿Por qué es obligatorio ejecutar `python pt_listener.py` primero?

                    

                        El script listener en pt-mcp-server\src\bridge\pt_listener.py actúa como el servidor socket TCP en el puerto 4242. Si intentas conectar la extensión de Packet Tracer antes de levantarlo, el script no encontrará ningún puerto abierto y la conexión fallará por Connection Refused. Por eso, el orden estricto siempre es: 1° Iniciar el Listener en la terminal ➡️ 2° Conectar el script en Packet Tracer.
                    

                

                

                    
¿Por qué dice "Waiting for your agent" o "Lost MCP server"?

                    

                        Es totalmente normal. La extensión de Packet Tracer incluye un mecanismo de File bridge de respaldo automático (🟢 verde). Aunque el puerto HTTP 54321 no esté retenido en ese segundo, las órdenes se envían por archivo local y se dibujan sin pérdida ni retraso.
                    

                

                

                    
¿Funciona en cualquier computadora o ruta?

                    

                        Sí. El archivo run_server.py y setup_project.py resuelven las rutas de Python y de los directorios de usuario dinámicamente en tiempo de ejecución, funcionando en Windows, macOS o Linux sin tocar nada a mano.
                    

                

                

                    
¿Cómo verificar que el agente tiene comunicación?

                    

                        Puedes pedirle a tu agente: "Ejecuta pt_master_catalog y dime qué routers tengo disponibles". Si responde con la lista de routers, el canal MCP está 100% operativo.
                    

                

                

                    
¿Se necesitan permisos de Administrador?

                    

                        No. Todo el servidor corre en el espacio de usuario estándar y no modifica archivos del sistema operativo protegidos.
